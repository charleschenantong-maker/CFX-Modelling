# 语言润色规范（POLISH-CONTRACT）

> 这份文件只为**语言润色**服务。章节结构、公式、数字、表格、代码、自测一律不动。
> 目标：把 ChatGPT 生成的生硬腔调改成人话，**但不牺牲严谨**。

判断标准一句话：

> **推导要正经，讲概念要说人话；读完这一节，读者知道自己下一步该打开哪个文件、敲哪一行、看到什么数字。**

---

## 1. 语域跟着内容走（最重要的一条）

不要全文一个调子。按内容类型选语域：

| 内容类型 | 语域 | 怎么写 |
|---|---|---|
| 数学推导、形式化定义、公式逐项解释 | **正式** | 保留"设……则……""由……可得""其中 \(x\) 表示……"。不要为了口语而拆散推导链条。术语首次出现给中英对照。 |
| 机制说明、"这东西是什么/为什么" | **中性偏口语** | 先一句大白话结论，再给形式化描述。可以用类比，但类比之后必须立刻回到具体对象。 |
| 直觉、类比、踩坑经验、"值不值" | **口语** | 用"你"。可以用短句、反问、具体场景（"你会看到 loss 突然变成 nan"）。 |
| 操作步骤、代码解析、命令 | **口语且命令式** | 直接说做什么、会看到什么。"这两行装依赖""跑完打印出……"。 |

**反例（不要这样）**：为了"接地气"，把 `由链式法则可得` 改成 `咱们顺着往下撸一下`。
**反例（也不要这样）**：讲"什么是蒸馏"时写 `知识蒸馏的范式迁移体现了表征空间的对齐约束`。

---

## 2. 绝对不能碰（改了就是事故）

1. **公式**：`\( ... \)`、`\[ ... \]` 内的所有内容，一个字符都不改；分隔符必须成对；公式内不得出现中文。
2. **数字**：所有数值、单位、默认值、超参、百分比，一律照抄。**发现数字互相矛盾时不要自己改，写进你的报告让 Lead 定夺。**
3. **HTML 结构**：标签、`class`、层级、属性一律不动。不新增、不删除任何元素。
   - `<h3>` 的**数量**不能变（目录靠它生成）。
   - 表格 `<thead>` 列数与 `<tbody>` 每行 `<td>` 数不能变。
   - `<div class="quiz">` 里**恰好一个 `data-ok`**，`<p class="why">` 必须保留。
4. **代码块**：`<pre><code>...</code></pre>` 里的代码一字不改（含缩进、注释、路径、参数）。
5. **元数据**：`COURSE.register({...})` 里的 `id / part / num / title / en / tags` 不动（`title` 也不动）。
6. **`String.raw` 技术约束**：正文里**不能出现反引号** `` ` ``，**不能出现 `${`**。要写代码标记就用 `<code>`。
7. **不能引入制表符**：严禁在正文/公式里出现真实 TAB 字符（历史事故：`\times` 被吃成 TAB，公式渲染成 "T imes d_k"）。需要缩进用空格。

## 3. 要改掉的（禁用清单）

### 3.1 营销腔
`打造 / 赋能 / 抓手 / 闭环 / 极致 / 终极 / 完美 / 巨头 / 碾压 / 震撼 / 惊人 / 陡降 / 暴降 / 无缝 / 游刃有余 / 登峰造极 / 秒杀`
→ 全部换成具体说法或直接删。
- ❌ 显存开销**暴降 80% 以上**！ → ✅ 显存占用降到原来的五分之一左右。
- ❌ 会**惊人地显示** → ✅ 会打印出。

### 3.2 感叹号与"让我们"
- 正文中的 `！` 基本全删（命令行示例、代码注释里的可保留）。
- `让我们……` / `我们` / `大家` / `读者` → 改成 `你`，或直接去掉主语。
- ❌ 让我们一起来探索 → ✅ 下面看它怎么算。

### 3.3 空话连接词
`首先 / 其次 / 再者 / 最后 / 值得注意的是 / 综上所述 / 总而言之 / 众所周知 / 不难发现 / 毋庸置疑 / 在……的背景下`
→ 删掉。段落之间靠内容衔接，不靠这些词报幕。
- ❌ 首先我们来看……其次……最后…… → ✅ 直接开始说第一件事。

### 3.4 名词化套话
`进行优化 / 实现提升 / 做出判断 / 对……进行处理 / 予以说明 / 加以改进 / 完成了……的构建`
→ 换回动词。
- ❌ 对学习率进行调优 → ✅ 调学习率
- ❌ 实现了吞吐量的提升 → ✅ 吞吐量上去了

### 3.5 程度副词堆砌
`极其 / 极为 / 非常 / 十分 / 相当 / 大幅度 / 显著地`
→ 要么删，要么给数字。
- ❌ 性能**显著**提升 → ✅ 吞吐从 180 tok/s 提到 320 tok/s（有数字就用数字）。

### 3.6 长句与被动
- 超过 ~45 字、含 2 个以上逗号从句的句子，拆成两句。
- 尽量少用"被"字句，改成主动。
- ❌ 该参数被优化器以二阶动量进行更新 → ✅ 优化器用二阶动量更新这个参数。

### 3.7 排比与空转
- `不仅……而且……更是……` / `既是……也是……` 这类排比，改成直接说结论 + 一个具体例子。
- 删掉"总的来说这是一件很有意义的事"这类没有信息量的收尾。

---

## 4. 要保留甚至加强的

- **手算例子**：步骤、数字、中间结果全保留。可以在开头加一句"跟着算一遍"。
- **失败模式**：`症状 → 原因 → 一行验证 → 对策` 的结构保留，措辞改口语。
- **具体优先**：能用文件名、命令、数字讲清的，不用形容词。
- **术语**：首次出现给「中文（English）」，之后再出现只用中文。
- **每节第一句**：尽量回答"我为什么要关心这一节"。

---

## 5. 自检（每改完一个文件都要跑）

```powershell
cd "D:\CFX Modelling\ai-course"
node --check content/<你的文件>.js
```

再人工确认：

1. 文件里**没有**反引号 `` ` ``、**没有** `${`、**没有**真实 TAB 字符。
2. 每个 `<div class="quiz">` 仍恰好一个 `data-ok`，仍有 `<p class="why">`。
3. 公式分隔符成对（`\(` 配 `\)`，`\[` 配 `\]`）。
4. `<h3>` 数量与改之前一致；表格列数一致。
5. 所有数字与改之前逐字一致。

**不要**运行 `tools/validate.mjs`（它检查整个仓库，别人还在改时会报一堆与你无关的错）；**不要**运行 `tools/bundle_content.py`（Lead 最后统一重打包）。
