# 课程写作与修改契约（高级章 17–24 深化 + 附录 G）

> 这份文件是**唯一的写作规范**。改动 `ai-course/content/` 下任何文件前先读完它。
> 目标读者：一个数学系背景、但可能没碰过大模型的**自学者**。判断标准很简单：
> **「接地气」= 读完这一节，读者知道自己下一步该打开哪个文件、敲哪一行命令、看到什么数字。**
> 做不到这一点，无论写得多「全」，都不算细致。

---

## 0. 铁律（违反即返工）

1. **只改自己负责的文件**。禁止碰 `index.html`、`README.md`、`90-appendix-a-glossary.js`、`91..95-appendix-*.js`、以及别人的章节文件。
2. **不要改 `COURSE.register({...})` 的元数据**（`id` / `part` / `num` / `title` / `en` / `minutes` / `tags` 全部保持原样，`minutes` 可小幅上调，其余不动）。
3. **不要改已有的正确内容**，只在合适位置**插入**新小节 / 新例子 / 新表格 / 新折叠块，并**新增**自测题（原有的自测题保留，可改写题干但必须仍然只有 1 个 `data-ok`，且逐字保留原有正确答案的编号顺序无所谓，但正确答案的**内容**不得改变）。
4. **只用模板里已存在的 HTML class**（见第 2 节白名单）。不要引入新样式、不要写 `<style>`、不要写行内 `style=`（模板里已有的除外）。
5. **数学一律用 KaTeX 分隔符**：行内 `\( ... \)`、行间 `\[ ... \]`。`\(` `\[` 必须在正文里成对出现；**公式里绝不能出现任何中文字符**（KaTeX 没有中文字形，会出现空白方块，验证脚本会直接报错）。
6. **字符串用 `String.raw\`...\``**：文件已经是这个形式，新增内容也放在同一个模板串里。注意：
   - 内容里**不能出现反引号 `` ` ``**（会提前结束模板串）——需要代码标记就用 `<code>` 标签。
   - 内容里**不能出现 `${`**（会被当成模板插值）。
   - 正文里要写 `\\(` 时照常写 `\(`（`String.raw` 会原样保留一个反斜杠），**不要**写成 `\\(`。
7. 写完后必须自测：`node --check <你的文件>`，并读一遍自己新写的段落，检查括号闭合、`</section>` 配对。

## 1. 这一轮的目标（用户原话：「17–24 不够细致」「要接地气」「不能是某个厂商专用的」）

- 17–24 八章是「高阶与前沿」，目前偏提纲。要往**能自学、能上手**的方向补。
- 每一章都必须显式回答三个问题：
  1. **这是什么**（一句话类比 + 它替代了什么朴素做法）；
  2. **怎么用手算一遍**（具体数字、具体步骤、能看到结果）；
  3. **我在自己项目里怎么用 / 什么时候绝对不该用**（对应 crossfade 音频建模项目）。
- **厂商中立**：不要写成「某某厂商的某个功能怎么点」。要写成「这件事在工程上叫什么、通用做法是什么、有哪些开源/开放协议/标准可选、怎么自己搭一个 30 行最小实现」。
  可以**举例**已知的产品或开源库（Hugging Face、TRL、vLLM、FAISS、BM25、LangGraph、MCP 等），但必须同时给「不依赖它」的通用做法，并避免把某一家的专有名词当作概念本身。
- **价格、额度、政策类数字**必须带出处与日期，或者干脆只给量级；不要编造精确数字。

## 2. 白名单：可用的 HTML 结构

### 版块（`<section class="blk ...">`，标题必须是 `<h4><span class="ic">符号</span>标题</h4>`）

| class | 用途 | 惯用图标 |
|---|---|---|
| `blk blk-tip` | 零基础入口、上手清单、经验法则 | `✓` |
| `blk blk-q` | 问题引入、一个真实场景 | `◆` |
| `blk blk-m` | 数学/公式推导 | `∑` |
| `blk blk-lab` | 动手：可运行代码、实验步骤 | `🧪` |
| `blk blk-warn` | 坑、失败模式、合规红线 | `⚠` |
| `blk blk-eco` | 怎么用回真实项目（必写！） | `◈` |

### 其它结构

- 表格：`<table class="tbl small"><thead><tr><th>…</th></tr></thead><tbody><tr><td>…</td></tr></tbody></table>`（列数要齐）
- 卡片网格：`<div class="grid2"><div class="card"><h5>标题</h5><p>…</p></div>…</div>`
- 流程图：`<div class="flow"><div class="nd hi">第一步</div><div class="ar">→</div><div class="nd">第二步</div>…</div>`
  （`.nd.hi` 只用于起始/重点节点；箭头是独立节点）
- 键值说明：`<dl class="kv"><dt>词</dt><dd>解释</dd></dl>`
- 折叠深入：`<div class="acc" data-t="标题" data-badge="进阶"><div class="acc-body"> … </div></div>`
- 术语悬浮：`<span class="t" data-tterm="English term" data-d="一句话定义（中文，具体到形状/默认值/失败模式）">中文词</span>`
- 代码：`<pre><code>…</code></pre>`，注释用 `<span class="cm"># 注释</span>`，关键字 `<span class="kw">`，字符串 `<span class="st">`。
  **代码里不要出现反引号和 `${`。**
- 小节标题一律 `<h3>`（会被自动收进「本讲速查」目录）。`<h4>` 只用于版块内部或三级小节。

### 自测题模板（每章末尾，新增题追加在原有题之后）

```html
<div class="quiz">
  <div class="qlabel">自测 · 4</div>
  <p class="q">题干（可以含 \( \) 公式与 &lt;code&gt;）</p>
  <ul class="opts">
    <li>错误选项</li>
    <li>错误选项</li>
    <li data-ok>正确选项</li>
  </ul>
  <p class="why">解析：说明为什么对、为什么其它三个错，并点出对应的失败模式。</p>
</div>
```

**硬性要求**：每题恰好一个 `data-ok`；`<p class="why">` 必须存在；错误选项要「像对的」（常见误解），不要凑数。

每章至少要**新增**：

1. **3 个手算 / 逐步走通的例子**（带具体数字、单位，能算出结果；用表格或有序列表展示步骤）。
2. **2 个新表格**（对照表 / 选型表 / 失败模式表，任选），且表格要能直接被当查表用。
3. **1 个「30 分钟最小实现」的动手版块**（`blk-lab`，含可运行代码或明确到命令级的步骤 + 要记录哪三个数字）。
4. **2 个新的 `<h3>` 小节**（每章 `h3` 总数 ≥ 7；`buildMiniToc` 会自动生成目录）。
5. **3–5 道新自测题**（原有题保留）。
6. **4–8 个新术语**写入 `_glossary/<章节号>.md`（见第 5 节格式）。
7. **`blk-eco`「怎么用在真实项目里」必须出现**，且必须明确说清「这个技术用在 crossfade 项目上值不值、为什么」。

## 5. 术语交付格式（写到 `ai-course/_glossary/<你的章节号>.md`）

每个文件只写**你负责章节**的新术语（不要重复附录 A 已有的；先搜一遍确认）。

```markdown
| 中文术语 | English | 一句话解释（含形状/默认值/失败模式，可含 LaTeX） |
|---|---|---|
| 投机解码 | Speculative decoding | 用一个小草稿模型连续猜 k 个 token，再由目标模型一次前向并行验证；接受率越高加速越多，草稿模型与目标模型分布越接近越好。 |
```

**格式约束**：
- 只能 3 列，表头与上面完全一致（不带前导/尾随空格的 `|` 行）。
- 中文术语 2–8 字，英文用原文术语。
- 一句话解释 30–80 字，必须给出可检验的信息（公式、默认值、规模、失败模式之一）。
- 公式用 `\( \)`，且公式内不得有中文。
- 每章 4–8 条。不要写「见第 X 节」这类无信息解释。
