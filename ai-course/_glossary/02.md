| 中文术语 | English | 一句话解释（含形状/默认值/规模、失败模式，可含 LaTeX） |
|---|---|---|
| 码点 | Code point | Unicode 给每个字符分配的整数，共 1114112 个；而字节只有 256 个，按码点建词表会让绝大多数 embedding 训练不足。 |
| 组合记号 | Combining mark | 码点落在 \(\mathrm{U+0300}\)–\(\mathrm{U+036F}\) 的附加符号（如 e 加尖音符成为 é）；旧版分词正则既不把它当字母也不当数字，会误切。 |
| 字节双射 | bytes_to_unicode | GPT-2 的 256 项映射，把字节对应到大于空格的可打印码点：空格变 Ġ（U+0120）、换行变 Ċ（U+010A），因此词表能当普通文本分发且可逆。 |
| 预分词 | Pre-tokenization | BPE 之前用正则切片段的那一步，GPT-4 规定数字片段最多 3 位；失败模式是把空白先切走，导致学不到带前导空格的 token。 |
| 合并秩 | Merge rank | 合并规则被学到的次序，推理时按 rank 递增套用；第 \(j\) 条规则产出的 token 秩为 \(j\)，因此一次扫描即收敛。 |
| 贪心次优 | Greedy suboptimality | BPE 只取当前频次最高的 pair，不看它对后续切分的影响；baaa×9、aaaa×2、aaa×1 只许合并一次时得 33 而非 20。 |
| 基数障碍 | Cardinality obstruction | 有限字母表与不可数集之间不存在单射；这条引理解释了文本 BPE 必可无损、音频残差量化必有损。 |
| 帧率 | Frame rate | codec 每秒输出多少帧 token；EnCodec 为 75 Hz、Mimi 为 12.5 Hz、英文文本约 4.5 token/s，直接决定序列长度。 |
| 码本 | Codebook | 量化器的码字集合，大小取 2 的幂；EnCodec 的 6 kbps 档用 8 个 1024 项码本，\(75\times8\times10=6000\) bit/s。 |
